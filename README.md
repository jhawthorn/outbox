# outbox

A git remote that holds pushes for human review before forwarding them to the real remote.

Push to `http://localhost:8080/<name>.git` instead of the upstream. A web UI shows each
branch's commits and diff against upstream. A human approves (outbox pushes to upstream)
or discards (staged branch is reset). Nothing reaches upstream without approval.

## Layout

- `lib/outbox/repo.rb` — one bare repo per name under `$OUTBOX_DATA/repos/<name>.git`.
  `refs/heads/*` is what was pushed here; `refs/remotes/upstream/*` is the real remote.
  A branch is pending when they differ. States: ready, new, deleted, diverged, synced.
- `lib/outbox/git_http.rb` — Rack middleware serving smart HTTP via `git http-backend`.
- `lib/outbox/app.rb`, `views/` — Sinatra UI. Routes: `/`, `/repos/:name`,
  `/repos/:name/branches/*`, plus POST `approve`, `discard`, `fetch`, `destroy`.
- `lib/outbox/git.rb` — git wrapper. Arguments as arrays, never a shell. Subprocesses get
  a minimal environment (`unsetenv_others`), not the server's.
- `lib/outbox/repo_actor.rb` — one Ractor per repo; the only thing that writes to it.
  Jobs (fetch, approve, discard) arrive on its port; it reports progress and results.
- `lib/outbox/hub.rb` — main-Ractor side: spawns actors, queues jobs, folds their events
  into a per-repo Status that the UI reads. Reads (branches, diffs) bypass the actor.
- `bin/outbox` — CLI for the same operations, synchronous, in its own process.

Pushes to upstream use `--force-with-lease` against the last fetched sha. Diverged
branches need an explicit force.

## Upstream auth

Each repo gets its own ed25519 keypair, generated by `ssh-keygen` when the repo is added
and stored next to it under `$OUTBOX_DATA/repos/<name>.git/deploy_key`. The repo page
shows the public half; add it to the upstream as a deploy key with write access. Git for
that repo runs with `GIT_SSH` set to `bin/outbox-ssh`, which git executes directly (no
shell) and which execs ssh with `-F /dev/null -i <key> -o IdentitiesOnly=yes`, so a key
can only ever reach its one upstream and `~/.ssh` is never read. Host keys are accepted
on first use into `$OUTBOX_DATA/known_hosts`.

HTTPS upstreams work too if the URL carries a token.

**Open question:** per-repo deploy keys mean a trip to GitHub's settings for every repo
added. The likely replacement is a single fine-grained GitHub token, scoped to the repos
the outbox may push to, passed as one environment variable and answered to git through
a `GIT_ASKPASS` program (no shell, no token on a command line). If that lands, the
deploy-key path goes away rather than living alongside it. Parked for now.

## Fetching

Upstream is fetched when a repo is added, once per repo at boot, and when you click
"Fetch upstream". Never on a timer.

## Run

```sh
bundle install
bundle exec puma -p 8080 config.ru          # data in ./data
bundle exec ruby test/smoke_test.rb         # end-to-end, uses a temp dir and a random port
```

Docker: `docker compose up -d --build`, then http://localhost:8080. Data lives in the
`outbox-data` volume. The UI and git endpoint have no auth; the compose file binds to
localhost only.
